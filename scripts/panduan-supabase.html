Bab 1

Mengapa Pilih Supabase?

Saat ini aplikasi menggunakan SQLite lokal yang tersimpan di file db/custom.db. Database ini hanya bertahan selama sandbox aktif — jika sandbox di-reset, semua data siswa, nilai, akun guru, bank soal, dan teks bacaan akan hilang. Untuk mengatasi masalah ini, kita perlu memindahkan database ke layanan cloud yang persisten.

Supabase adalah layanan backend-as-a-service berbasis PostgreSQL yang menawarkan free tier sangat dermawan. Berikut perbandingan dengan alternatif lain:

Layanan Free Tier Kelebihan
Supabase ⭐ 500 MB DB
50K req/bulan		 Dashboard web, mudah dipakai, fitur lengkap (auth, storage, realtime)
Neon 0.5 GB
100 jam compute/bln		 Performa PostgreSQL murni, branching untuk dev
Turso 9 GB, 500 DB
Edge global		 Migrasi paling mudah dari SQLite, latency rendah

Saya merekomendasikan Supabase karena: (1) gratis selamanya selama akun aktif, (2) punya dashboard web untuk melihat data langsung tanpa coding, (3) kapasitas 500 MB cukup untuk puluhan ribu siswa, dan (4) dokumentasi dan komunitasnya sangat baik.

Bab 2

Persiapan Sebelum Mulai

Sebelum memulai migrasi, pastikan Anda sudah menyiapkan hal-hal berikut. Persiapan yang baik akan membuat proses migrasi berjalan lancar tanpa kendala.

1Akun Email

Siapkan akun email aktif (Gmail, Outlook, atau lainnya) untuk daftar Supabase. Email ini akan menjadi akun utama untuk mengelola database.

2Browser Modern

Gunakan Chrome, Edge, atau Firefox versi terbaru untuk mengakses dashboard Supabase. Hindari browser lama atau tidak umum.

3Koneksi Internet Stabil

Pastikan internet stabil selama setup (sekitar 10–15 menit). Koneksi terputus di tengah proses bisa menyebabkan konfigurasi gagal.

4Backup Data Lama

Jika sudah ada data siswa di SQLite, lakukan Export CSV dari dashboard guru (tab "Hasil Siswa" → tombol "Export CSV"). Simpan file CSV sebagai backup.

Bab 3

Daftar & Buat Project Supabase

Pada bab ini kita akan mendaftar akun Supabase dan membuat project database baru. Ikuti setiap langkah dengan teliti.

1

Buka Website Supabase

Kunjungi https://supabase.com di browser. Klik tombol "Start your project" di pojok kanan atas.

2

Login dengan GitHub

Supabase menyarankan login dengan akun GitHub (paling mudah). Klik "Sign in with GitHub". Jika belum punya akun GitHub, daftar dulu di github.com (gratis). Alternatif: klik "Sign in with Email" untuk pakai email langsung.

3

Authorize Supabase

Jika pakai GitHub, akan muncul halaman otorisasi. Klik "Authorize supabase". Anda akan diarahkan kembali ke dashboard Supabase.

4

Buat Project Baru

Di dashboard, klik tombol "New project". Pilih organization (default: akun Anda). Isi form project:

# Contoh pengisian: Name: Latihan Komputasional SMP Database Password: buat password kuat (12+ karakter, campuran huruf, angka, simbol) ⚠️ SIMPAN PASSWORD INI AMAN! Region: Southeast Asia (Singapore) ← pilih terdekat untuk latency rendah Pricing Plan: Free tier ($0/month)
5

Tunggu Provisioning

Klik "Create new project". Supabase akan menyiapkan database (sekitar 2–3 menit). Jangan tutup halaman sampai status berubah dari "Setting up project" menjadi hijau "Ready".

⚠️ Penting: Simpan Password

Database password tidak bisa dilihat lagi setelah dibuat. Catat di tempat aman (password manager / catatan). Jika lupa, harus reset password dan update konfigurasi aplikasi.

Bab 4

Ambil Connection String

Setelah project siap, kita perlu mengambil connection string — URL yang dipakai aplikasi untuk terhubung ke database Supabase.

1

Buka Settings Database

Di sidebar kiri dashboard Supabase, klik icon ⚙️ Settings (paling bawah). Lalu pilih menu "Database".

2

Cari Connection String

Scroll ke bawah sampai menemukan bagian "Connection string". Pilih tab "URI". Anda akan melihat URL dengan format:

postgresql://postgres.[PROJECT-REF]:[YOUR-PASSWORD]@aws-0-[REGION].pooler.supabase.com:6543/postgres
3

Copy & Ganti Password

Copy URL tersebut. Ganti bagian [YOUR-PASSWORD] dengan password yang Anda buat di Bab 3 langkah 4. Hasil akhir:

postgresql://postgres.abc123xyz:MyStr0ng!Pass@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres
🚫 Jangan Share URL Ini

Connection string berisi password database Anda. Jangan pernah share di grup WhatsApp, screenshot publik, atau commit ke repository Git publik. Hanya untuk konfigurasi aplikasi.

Bab 5

Migrasi Aplikasi ke Supabase

Saya sudah menyiapkan script otomatis yang akan mengkonfigurasi aplikasi Anda untuk terhubung ke Supabase. Script ini akan: backup SQLite lama, update schema, update .env, push tabel, dan seed data awal (akun guru + 60 soal + 5 teks bacaan).

1

Jalankan Script Migrasi

Buka terminal di project, jalankan perintah berikut. Script akan meminta Anda memasukkan connection string Supabase:

npx tsx scripts/migrate-to-supabase.ts
2

Masukkan DATABASE_URL

Saat muncul prompt "Masukkan DATABASE_URL Supabase Anda:", paste connection string dari Bab 4 langkah 3, lalu tekan Enter.

3

Konfirmasi Migrasi

Script akan konfirmasi "Lanjutkan? (ketik 'ya')". Ketik ya dan Enter. Tunggu 1–2 menit sampai muncul pesan "✅ MIGRASI BERHASIL!".

4

Restart Server

Setelah migrasi sukses, restart server dengan:

# Stop server lama (Ctrl+C), lalu jalankan: bun run dev
5

Verifikasi di Dashboard Guru

Buka aplikasi → login sebagai guru (guru / guru123) → tab "Bank Soal". Pastikan 60 soal muncul. Cek juga tab "Teks Bacaan" — harus ada 5 teks (8A, 8B, 8C, 9A, 9B).

✅ Migrasi Selesai!

Database Supabase sekarang berisi: 1 akun guru, 60 soal HOTS, 5 teks bacaan. Data siswa baru yang mengerjakan latihan akan langsung tersimpan ke Supabase — tahan terhadap reset sandbox.

Bab 6

Cara Manual (Jika Script Gagal)

Jika script otomatis gagal atau Anda ingin kontrol penuh, lakukan migrasi manual dengan 3 langkah berikut.

AEdit prisma/schema.prisma

Buka file prisma/schema.prisma. Ubah provider dari sqlite menjadi postgresql:

# Sebelum: datasource db { provider = "sqlite" url = env("DATABASE_URL") } # Sesudah: datasource db { provider = "postgresql" url = env("DATABASE_URL") }

BEdit file .env

Buka file .env di root project. Ganti baris DATABASE_URL dengan connection string Supabase Anda:

# Sebelum: DATABASE_URL="file:./db/custom.db" # Sesudah (ganti dengan URL Anda): DATABASE_URL="postgresql://postgres.abc123:PasswordAnda@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres"

CJalankan 3 Perintah Ini

Di terminal, jalankan perintah berikut secara berurutan:

# 1. Buat tabel di Supabase bun run db:push # 2. Buat akun guru default npx tsx scripts/seed-teacher.ts # 3. Isi 60 soal + 5 teks bacaan npx tsx scripts/seed-content.ts # 4. Restart server bun run dev
Bab 7

Verifikasi & Cek Database

Setelah migrasi, verifikasi bahwa data sudah tersimpan di Supabase dengan benar. Ada 2 cara: via aplikasi dan via dashboard Supabase.

1Via Aplikasi

Buka aplikasi siswa, coba daftar sebagai siswa baru. Setelah selesai latihan, login sebagai guru dan cek apakah nilai siswa muncul di "Hasil Siswa". Jika ya, integrasi Supabase berhasil.

2Via Dashboard Supabase

Di dashboard Supabase, klik 📊 Table Editor di sidebar kiri. Anda akan melihat daftar tabel: Student, Teacher, Question, TypingText, Result. Klik tabel mana pun untuk lihat isinya langsung.

💡 Tip: Tambah Akun Guru Lain

Di dashboard Supabase → Table Editor → tabel Teacher → klik "Insert row". Isi username, password (hash SHA-256), dan name. Atau minta saya buatkan script tambah guru via CLI.

Walaupun Supabase sangat reliable, tetap lakukan backup berkala untuk berjaga-jaga. Berikut strategi backup yang direkomendasikan.

Frekuensi Apa yang Dibackup Cara

Bab 9

Troubleshooting

Berikut masalah yang sering muncul saat migrasi dan cara mengatasinya.

Error: "Can't reach database server"

Penyebab: Connection string salah atau network memblokir port 6543.
Solusi: Cek ulang connection string. Pastikan tidak ada spasi. Coba pakai koneksi internet lain. Jika di sekolah/kantor, tanyakan ke admin apakah port 6543 diblokir.

Error: "password authentication failed"

Penyebab: Password salah atau ada karakter khusus yang perlu di-encode.
Solusi: Pastikan password sesuai. Jika password mengandung @ : / # ?, encode ke URL format (mis. @ → %40). Atau ganti password jadi lebih sederhana (hanya huruf+angka).

Error: "database does not exist"

Penyebab: Project Supabase belum selesai dibuat atau salah pilih project.
Solusi: Cek di dashboard Supabase apakah project status "Ready". Pastikan copy connection string dari project yang benar.

Error: "relation already exists"

Penyebab: Tabel sudah ada di database (dari percobaan sebelumnya).
Solusi: Aman, ini hanya warning. Lanjutkan ke step seed data. Jika bermasalah, jalankan bun run db:reset untuk reset database (⚠️ hapus semua data!).

⚠️ Jangan Reset Database Production

Perintah bun run db:reset akan menghapus semua data (siswa, nilai, soal, teks). Hanya jalankan jika yakin ingin mulai dari nol. Selalu backup dulu!

Bab 10

Rollback ke SQLite (Jika Perlu)

Jika Supabase bermasalah dan ingin kembali ke SQLite lokal, lakukan langkah berikut. Data SQLite lama sudah dibackup otomatis oleh script migrasi.

1

Edit prisma/schema.prisma

Ubah provider kembali ke sqlite:

datasource db { provider = "sqlite" url = env("DATABASE_URL") }
2

Edit file .env

Kembalikan DATABASE_URL ke SQLite:

DATABASE_URL="file:./db/custom.db"
3

Restore SQLite Backup

Cari file backup di folder db/ dengan nama custom.db.backup-XXXXXX. Rename kembali ke custom.db.

4

Regenerate & Restart

Jalankan perintah berikut:

bun run db:generate bun run db:push bun run dev
